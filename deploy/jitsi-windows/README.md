# Jitsi + Jigasi на Windows — развёртывание «одной кнопкой»

Полный стек Jitsi Meet (web + prosody + jicofo + jvb) с транскрайбером
**jigasi**, подключённым к серверу «Стенографа» на этой же машине.
Аналог стенда на Linux-ВМ (`192.168.0.15`), но локально на Windows.

## Можно ли вообще на Windows?

Да — через **Docker Desktop** (движок WSL2), и это рабочий вариант для демо
и разработки. Что честно стоит знать:

- Официально `docker-jitsi-meet` ориентирован на Linux. На Windows всё
  работает, но «нюансы платформы» — UDP-медиа и firewall — требуют внимания
  (см. «Если что-то не работает»). Мы их учли.
- Это **стенд для демонстрации/разработки**. Для постоянной работы и больших
  встреч (десятки участников) лучше держать Jitsi на Linux-ВМ, как сейчас.
- Первый запуск скачивает ~1,5 ГБ образов из ghcr.io.
- Никаких секретов здесь нет: пароли генерируются на машине при первом
  запуске (`.env` в репозиторий не попадает).

## Требования

- Windows 10/11 x64, в BIOS включена виртуализация (VT-x / AMD-V).
- **Docker Desktop** с Linux-контейнерами: `winget install Docker.DockerDesktop`
  (или https://www.docker.com/products/docker-desktop/). При первом запуске
  выбрать бэкенд WSL2.
- ~2–4 ГБ свободной RAM (стек занимает ~2 ГБ).
- Свободные порты: **8081**, **8443** и **10000/udp** (плюс 8080 и 8888 на
  127.0.0.1). Занято — поменяйте `HTTP_PORT`/`HTTPS_PORT`/`JVB_PORT` в `.env`.
- Для доверенного сертификата (чтобы у гостей не было предупреждений
  браузера) — **Git for Windows**. Без него всё тоже работает, но на
  встроенном самоподписанном сертификате.

## Запуск «одной кнопкой»

Двойной клик по **`start.bat`** (первый раз удобно «Запуск от имени
администратора» — тогда он добавит правила Windows Firewall для LAN).

`start.bat` делает 6 шагов:

1. создаёт `.env` (случайные пароли + LAN-адрес этой машины), если его нет;
2. проверяет Docker Desktop и сам запускает его, если тот не запущен;
3. добавляет правила firewall для 8443/tcp, 8081/tcp, 10000/udp
   (без прав администратора шаг тихо пропускается);
4. выпускает сертификат от локального CA «Stenograph Local CA»
   (папка `ca\` + `config\web\keys\`);
5. поднимает контейнеры (`docker compose ... up -d`; первый раз — долгое
   скачивание образов) и сам лечит известную гонку первого запуска:
   если jigasi попробовал войти до того, как prosody создал его учётку,
   в его логе появляется `not-authorized` — start.bat перезапускает
   transcriber один раз (на последующих запусках этого не происходит);
6. ждёт страницу и печатает адрес.

Повторный запуск `start.bat` — просто поднять/обновить. Остановить —
**`stop.bat`** (данные в `config\` сохраняются).

Для неинтерактивного запуска: `set STENOGRAPH_NOPAUSE=1`.

## Доступ

- На этой машине и в LAN: `https://192.168.0.9:8443` (адрес/порт печатает
  start.bat; они лежат в `.env`: `PUBLIC_URL`, `DOCKER_HOST_ADDRESS`).
- Комната — любое имя после слэша: `https://<адрес>:8443/МояВстреча`
  (лучше латиницей без пробелов).
- Сменить IP/порт: отредактировать `.env` → снова `start.bat`.
  Если сменился IP машины — перевыпустить сертификат (см. ниже).

## Сертификаты (доступ без предупреждений браузера)

При первом запуске `start.bat` создаёт локальный CA и выпускает для этой
машины сертификат на её LAN-IP. Чтобы гости заходили без предупреждений:

1. Скопировать гостю два файла из папки `ca\` и корня: **`ca.crt`** и
   **`install-ca.bat`**.
2. Гость запускает `install-ca.bat` двойным кликом (без админа), полностью
   закрывает браузер и открывает страницу снова.

Сменился IP машины → сертификат перевыпустить: удалить папки `ca\` и
`config\web\keys\`, запустить `start.bat`, раздать новый `ca.crt`.

## Связка со «Стенографом»

Jigasi в режиме транскрайбера соединяется с сервером «Стенографа» на этой
же машине: `JIGASI_TRANSCRIBER_WHISPER_URL=ws://host.docker.internal:8000/ws`
(в `.env`). Сервер «Стенографа» (`start_server.bat`) должен быть запущен.

Как включается транскрипция: в комнате модератор → **«More actions» →
«Closed captions» → «Start closed captions»**. Jigasi заходит в комнату
скрытым участником и стримит аудио каждого говорящего в «Стенограф»;
субтитры идут в Jitsi, а у нас появляется живая задача «Jitsi-сессия …».
Полное описание потока и диагностика — `docs/JITSI.md` в корне репозитория.

Проверка:

```bat
docker ps                          :: все 5 контейнеров Up
docker logs docker-jitsi-meet-transcriber-1 --tail 50
docker exec docker-jitsi-meet-transcriber-1 wget -qO- http://host.docker.internal:8000/api/health
```

(последняя команда проверяет, что из контейнера виден «Стенограф»).

Проверено вживую (10.10.2026, на этой машине): полный путь комнаты —
вход в `StenoWindows` → CC → jigasi зашёл скрытым участником →
`Successfully connected to ws://host.docker.internal:8000/ws/<id>` →
в «Стенографе» появилась живая задача «Jitsi — …» → выход из комнаты →
jigasi закрыл сессию, задача стала `done`. Доступ по LAN проверен с
Linux-ВМ (`code=200` с `https://192.168.0.9:8443/`).

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `start.bat`: «Docker Desktop did not come up» | Открыть Docker Desktop руками, дождаться «Engine running», повторить |
| Страница открывается, но участники не слышат друг друга (ICE failed) | Проверить, что UDP 10000 свободен и разрешён (антивирус/файрвол). На Windows 11 можно включить зеркальную сеть WSL: `%UserProfile%\.wslconfig` → `[wsl2]` + `networkingMode=mirrored`, затем `wsl --shutdown` и перезапуск Docker Desktop |
| Предупреждение сертификата у гостей | Раздать `ca.crt` + `install-ca.bat` (см. выше) |
| Порт занят | Поменять `HTTP_PORT`/`HTTPS_PORT` в `.env`, перезапустить `start.bat` |
| Субтитры не идут | См. «Проверка» и раздел диагностики в `docs/JITSI.md` |
| Логи | `docker compose -f docker-compose.yml -f transcriber.yml logs -f web jvb transcriber` |
| Обновить образы | `docker compose -f docker-compose.yml -f transcriber.yml pull` + `up -d`. Зафиксировать версию: `JITSI_IMAGE_VERSION=stable-XXXX` в `.env` (по умолчанию `unstable` — как на ВМ) |

## Состав папки

| Файл | Что это |
|---|---|
| `start.bat` | «Одна кнопка»: подготовка + запуск всего стека |
| `stop.bat` | Остановить стек (данные сохраняются) |
| `.env.template` | Шаблон окружения (без секретов); `.env` создаётся при запуске |
| `prepare_env.ps1` | Генерирует `.env`: LAN-IP, случайные пароли |
| `make_cert.sh` | Локальный CA + сертификат (запускается из start.bat через Git) |
| `install-ca.bat` | Для гостей: поставить `ca.crt` в доверенные (без админа) |
| `docker-compose.yml` | Стек из проекта `docker-jitsi-meet` (Apache-2.0), как на ВМ |
| `transcriber.yml` | Наш override: пятый контейнер `transcriber` (jigasi) |
| `config\` | Генерируется контейнерами при первом запуске (не коммитится) |
| `ca\` | Локальный CA и ключи (не коммитится) |

## Ограничения

- Субтитры включаются вручную модератором (кнопкой в комнате).
- Одна встреча «тяжёлая» эффективно одна за раз — распознавание идёт на GPU
  этой же машины (сервер «Стенографа»).
- Если встреча идёт не в вашем Jitsi — серверного способа нет, только
  локальный захват (микрофон + системный звук) в самом «Стенографе».
