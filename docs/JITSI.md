# Jitsi: интеграция через Jigasi

Шпаргалка по вопросу «как „Стенограф“ подключён к Jitsi»: что настроено, где,
как проверить и что делать, если субтитры не идут.

## Идея

Jitsi сам звук встречи наружу не отдаёт. Штатный компонент **Jigasi** (входит
в дистрибутив Jitsi) умеет заходить в конференцию виртуальным участником и
транскрибировать её: он получает аудио каждого говорящего **отдельным потоком**
и отправляет его во внешний сервис распознавания. Jitsi поддерживает внешние
Whisper-сервисы по открытому протоколу (streaming-whisper; им пользуется и
проект `jitsi/skynet`).

«Стенограф» реализует этот протокол — для Jitsi он выглядит как обычный
Whisper-сервис субтитров. В самом Jitsi ничего не патчилось: только
конфигурация штатного механизма.

## Схема потока

```
Участники (браузер, телефон, переговорка)
        │  WebRTC-аудио
        ▼
JITSI на ВМ <адрес-Jitsi>  (web + prosody + jicofo + jvb)
        │  Jigasi-транскрайбер заходит в комнату скрытым участником
        │  и получает ОТДЕЛЬНЫЙ аудиопоток на каждого говорящего
        ▼
Jigasi (5-й контейнер, transcriber)
        │
        │  WebSocket →  ws://<адрес-стенографа>:8000/ws/<сессия>
        │  туда: бинарные кадры = заголовок (id участника + язык) + PCM 16 кГц
        │  обратно: JSON {partial / final, participant_id, text}
        ▼
«СТЕНОГРАФ» на Windows (<адрес-стенографа>, GPU)
   whisper на GPU · отдельный распознаватель на каждого участника ·
   WAV-дорожки + сегменты в базу + живая задача в веб-интерфейсе
```

Титры ходят по кругу: **Jitsi → Jigasi → Стенограф → Jigasi → Jitsi**.
Параллельно «Стенограф» ведёт полный транскрипт встречи у себя.

## Что происходит при встрече (пошагово)

1. Встреча идёт в Jitsi как обычно.
2. Модератор включает субтитры: «More actions» → «Closed captions» →
   «Start closed captions».
3. Jitsi поднимает транскрайбер-сессию: Jigasi подключается к комнате скрытым
   участником.
4. Jigasi открывает WebSocket к «Стенографу» (адрес из своей конфигурации —
   `whisper.websocket_url`). Дозванивается он сам, не мы к нему.
5. Аудио каждого говорящего уходит к нам отдельным потоком с его id.
6. «Стенограф» распознаёт речь (крупная whisper-модель на GPU) с контекстом
   по каждому участнику и выдаёт partial (промежуточный) и final
   (зафиксированный) текст.
7. Текст мгновенно возвращается в Jigasi тем же сокетом → Jitsi показывает
   субтитры всем участникам.
8. Параллельно у нас: WAV-дорожка каждого участника в `data/jitsi/<задача>/`,
   сегменты «Спикер N: …», живая задача «Jitsi-сессия …» в вебе.
9. Встреча закончилась → задача закрывается: транскрипт по спикерам, экспорт
   TXT/SRT/JSON, далее кнопками — протокол или резюме локальной LLM.

## Протокол обмена (streaming-whisper)

- **URL:** `ws://<хост>:<порт>/ws/<id сессии>` — идентификатор генерирует Jigasi.
- **Кадр:** 60-байтный заголовок `participantId|language` (UTF-8, добит нулями)
  + сырой звук: **int16, 16 кГц, моно**.
- **Конец потока:** один нулевой байт.
- **Ответ:** JSON `{"type": "partial"|"final", "participant_id": …, "text": …,
  "variance": …}`.

Формат сверен с обеих сторон: `WhisperWebsocket.java` (Jigasi) и
`utils.load_audio` из `jitsi/skynet` (streaming_whisper).

## Конфигурация

### Сторона Jitsi (ВМ `<адрес-Jitsi>`, `~/docker-jitsi-meet`)

`.env` (бэкап: `.env.bak.stenograph`):

```bash
ENABLE_TRANSCRIPTIONS=1
JIGASI_TRANSCRIBER_CUSTOM_SERVICE=org.jitsi.jigasi.transcription.WhisperTranscriptionService
JIGASI_TRANSCRIBER_WHISPER_URL=ws://<адрес-стенографа>:8000/ws
PREFERRED_LANGUAGE=ru-RU      # язык распознавания по умолчанию
USE_APP_LANGUAGE=0            # не подменять языком интерфейса
```

Запуск (профиль `transcriber.yml` добавляет пятый контейнер — Jigasi):

```bash
docker compose -f docker-compose.yml -f transcriber.yml up -d
```

Итоговый конфиг внутри Jigasi
(`/run/jigasi/config/sip-communicator.properties`):

```
org.jitsi.jigasi.ENABLE_TRANSCRIPTION=true
org.jitsi.jigasi.transcription.customService=org.jitsi.jigasi.transcription.WhisperTranscriptionService
org.jitsi.jigasi.transcription.whisper.websocket_url=ws://<адрес-стенографа>:8000/ws
```

### Сторона «Стенографа» (Windows, `<адрес-стенографа>`)

- Сервер должен слушать `0.0.0.0:8000` (`start_server.bat` уже так) — иначе
  Jigasi с ВМ не достучится.
- Эндпоинт моста: `WS /ws/{meeting_id}`.

## Код

- `bridge/protocol.py` — формат обмена (заголовок, PCM, EOF, JSON-ответы).
- `bridge/session.py` — сессия комнаты: StreamTracker и WAV на каждого
  участника, сегменты в БД и шину событий, финализация задачи.
- `bridge/manager.py` — реестр сессий по meeting_id (замена устаревших при
  переподключении Jigasi).
- `api/app.py` — эндпоинт `WS /ws/{meeting_id}` + отправка caption-сообщений.

## Проверка и диагностика

1. Сервер жив и слышен снаружи:
   - на Windows: `curl http://127.0.0.1:8000/api/health`
   - с ВМ: `curl http://<адрес-стенографа>:8000/api/health` → `{"status":"ok", ...}`
2. Логи моста (Windows, вывод сервера):
   - «jitsi bridge: websocket подключён (…)» — Jigasi дозвонился;
   - «jitsi bridge: участник … → «Спикер N»» — пошли потоки участников.
3. Логи Jigasi (ВМ): `docker logs -f docker-jitsi-meet-transcriber-1`.
4. В вебе «Стенографа» появляется задача «Jitsi-сессия …», сегменты идут
   в реальном времени.

Если субтитры не идут:

- нет «websocket подключён» → проверить `JIGASI_TRANSCRIBER_WHISPER_URL` и что
  порт 8000 открыт (netstat/фаервол);
- «подключён», но участников нет → пере-включить CC в конференции;
- русская речь уходит в перевод на английский → проверить
  `PREFERRED_LANGUAGE=ru-RU`, `USE_APP_LANGUAGE=0` и перезапустить контейнер
  `web`.

## Ограничения (ответы на вопросы)

- «Стенограф» должен быть сетевой доступен со стороны Jitsi (в пилоте — одна
  LAN).
- Субтитры включаются вручную модератором.
- Последний участник вышел → Jigasi завершает сессию (транскрайбер привязан
  к встрече).
- Одна GPU: тяжёлая встреча эффективно одна за раз, остальное — очередь.
- Язык задаётся на сервере (`PREFERRED_LANGUAGE`); whisper умеет и другое.
- Если встреча идёт не в вашем Jitsi — серверного способа нет, только
  локальный захват (микрофон + системный звук).

## Как объяснить руководителю (в двух предложениях)

Мы встроились в корпоративный Jitsi штатным механизмом Jigasi: сервер сам
заходит во встречу тихим участником, получает аудио каждого говорящего
отдельно и передаёт нашему сервису распознавания по внутренней сети.
Распознавание и последующая ИИ-обработка идут на нашей машине — данные не
уходят в облако; участникам ничего не нужно устанавливать, а после встречи
сразу готовы транскрипт по спикерам и протокол.

- Конфиг Jigasi подтверждён (customService + whisper.websocket_url).
- Комната `stenograph-demo` (`https://<адрес-Jitsi>/`): субтитры появлялись
  в панели Jitsi, после фикса языка — корректный русский текст.
